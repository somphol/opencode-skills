# Deployment

## GitHub Pages

The site is static and path-relative. It is served from **`main`, repository root** with no build
step.

- Live: <https://somphol.github.io/aurelis-calibre-07/>
- Repository: <https://github.com/somphol/aurelis-calibre-07>
- Pages source: **Deploy from a branch → `main` → `/ (root)`**

`.nojekyll` is committed so GitHub Pages does not run Jekyll over the files. Every asset path is
relative (`./vendor/...`, `./fonts/...`, `./screenshots/...`), so the site works at a repository
subpath and would work at a custom domain without edits.

## Publish a change

```sh
npm run verify
git add -A
git commit -m "…"
git push origin main
```

Pages rebuilds automatically, usually within a minute. Check:

```sh
curl -s -o /dev/null -w "%{http_code}\n" https://somphol.github.io/aurelis-calibre-07/
```

### Cache

GitHub Pages caches aggressively. A hard reload (`Cmd/Ctrl + Shift + R`) or a new query string
(`?v=2`) is the reliable way to see a change. The site has no service worker; there is no stale
offline copy to clear.

## Custom domain

If a domain is added later:

1. Add `CNAME` with the domain at the repository root.
2. Enable HTTPS in Pages.
3. Update `canonical`, `og:url`, `og:image`, `sitemap.xml` and `robots.txt`.
4. Update the live URL in `README.md`, `AGENTS.md`, `state.json` (via `npm run state`) and the
   colophon if the domain is mentioned.

## Rollback

Pages serves the current `main`. To roll back, revert the offending commit and push; or re-run the
Pages deployment from an earlier commit. The site has no server state to migrate.

## The skill catalog

The companion skill is published separately in the OpenCode skills catalog
(`somphol/opencode-skills`), served from <https://somphol.github.io/opencode-skills/>. Its `index.json`
is generated by `sync.mjs` from `skills.json`; do not hand-edit the catalog's skill folders. The
project's own release is independent of the catalog release.

## What is not deployed

- `node_modules/` and the Puppeteer dependency (dev-only).
- The OpenCode session database and any local state.
- Session transcripts.
