# Release

## Documentation

A release needs, at minimum:

- `README.md` — what, live URL, brief, run/verify, architecture, credits, licence.
- `AGENTS.md` — the one-minute handoff: commands, layout, invariants, known issues, continuity.
- `CREDITS.md` — the prompt, the fine print, OpenCode/model/Three.js/fonts/source video.
- `STATE.md` + `state.json` — generated session ledger (time, tokens, model, build stats).
- `LICENSE`, `THIRD_PARTY_NOTICES.md`, `CITATION.cff`, `CHANGELOG.md`.
- `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, `SUPPORT.md`.
- `docs/ARCHITECTURE.md`, `TIMELINE.md`, `BUILD-LOG.md`, `STUDY.md`, `VERIFICATION.md`,
  `REPRODUCE.md`, `DEPLOYMENT.md`, `DESIGN.md`.
- `robots.txt`, `sitemap.xml`, `404.html`, `.nojekyll`.
- Screenshots regenerated by the gate.

No emails, tokens or machine paths. The skill-publish checker flags emails in source files.

## Ledger

```sh
npm run state
```

`scripts/state.mjs` opens OpenCode's local SQLite database read-only, reads the current session row
(`OPENCODE_SESSION_ID`), and writes aggregate timing/tokens. It copies no conversation content and no
machine path. The session remains open while publishing, so the file is a release-prep snapshot;
state that honestly.

## Pages

1. Repository → Settings → Pages → Deploy from a branch → `main` → `/ (root)`.
2. Ensure `.nojekyll` exists.
3. Keep all asset paths relative.
4. Poll: `curl -s -o /dev/null -w "%{http_code}" https://<user>.github.io/<repo>/`.
5. Update `canonical`, `og:url`, `og:image`, `sitemap`, `robots`, README and AGENTS with the live URL.

## No-gh publish without repeated keychain prompts

Do all GitHub work in **one** shell script, fetch the credential once, and never print it:

```sh
CRED=$(printf "protocol=https\nhost=github.com\n\n" | git credential fill)
TOKEN=$(printf '%s\n' "$CRED" | sed -n 's/^password=//p')
USER=$(printf '%s\n' "$CRED" | sed -n 's/^username=//p')

# Create the repo once:
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Accept: application/vnd.github+json" \
  https://api.github.com/user/repos \
  -d '{"name":"my-watch","private":false,"has_wiki":false,"has_projects":false}'

# Push without embedding the token in .git/config:
AUTH=$(printf "x-access-token:%s" "$TOKEN" | base64)
git push -c "http.extraHeader=Authorization: Basic $AUTH" -u origin main

# Enable Pages:
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/$USER/my-watch/pages \
  -d '{"source":{"branch":"main","path":"/"}}'
```

`gh` is optional. One `git credential fill` is the only Keychain access; reuse the token for the API,
the push and the catalog in the same script. Fine-grained tokens need repo creation + Pages
permissions.

## Skill catalog

For an existing OpenCode catalog:

1. Put the skill at `~/.config/opencode/skills/<id>`.
2. Run the validator:
   `node ~/.config/opencode/skills/skill-publish/scripts/check-skill.mjs <dir> --strict`.
3. Add an entry to the catalog's `skills.json` and run `node sync.mjs <id>`.
4. Add a README row; commit and push.
5. Check `https://<user>.github.io/<catalog>/index.json` contains the new version.

The catalog is a full copy; bump its content hash by changing a file. Do not hand-edit generated
skill folders.
